# VitaStore — Offline-mode strategy: работа магазина при обрыве связи и синхронизация данных

## Механизм работы офлайн-режима

Предлагается создать **Store Edge Gateway** — компактный сервис, который работает на планшете кассира рядом с тонким 
клиентом Cloud POS. Помимо функций Hardware Abstraction Layer / Payment Gateway для фискального регистратора и 
разнородных банковских терминалов, Gateway держит локальный **read-only кэш мастер-данных** (SKU, цены, 
снимок правил Promo Engine, справочники, лимиты и балансы карт лояльности по клиентам магазина) и 
локальную **очередь исходящих событий (outbox)** на встроенной БД. Кэш обновляется из облака инкрементально в течение 
дня и рассчитан на автономную работу магазина до 24 часов, поэтому обрыв канала провайдера не требует ни выезда 
инженера, ни повторной настройки.

При потере связи Cloud POS автоматически переключается на локальный API того же Gateway — интерфейс кассира и порядок 
действий не меняются, кассир видит только индикатор «офлайн». Продажа за наличные проходит полностью локально: 
чек рассчитывается по кэшированным ценам и промо-правилам, фискализация выполняется фискальным регистратором и 
фискальным накопителем, который по закону хранит документы локально и допускает отложенную передачу в ОФД, тогда 
покупатель получает валидный фискальный чек. Оплата картой возможна в пределах автономного режима самого терминала 
и правил банка-эквайера. 

Ключевое отличие от текущей ситуации (INC-8402) — **функциональность лояльности больше не блокирует продажу** при 
отсутствии интернета: идентификация карты и начисление баллов выполняются локально по кэшу и уходят в облако отложено, 
а списание баллов разрешено в пределах кэшированного баланса и офлайн-лимита на транзакцию, чтобы ограничить финансовый 
риск двойного списания. Недоступными офлайн остаются только операции, которые физически требуют централизованных 
данных: оформление новых заказов Click & Collect, персональные промо, рассчитанные в реальном времени, и возвраты 
по чекам других магазинов сети. 

## Синхронизация при восстановлении связи

Все офлайн-операции пишутся в локальный outbox как неизменяемые события (чек, оплата, начисление/списание баллов, 
движение товара) с уникальным идемпотентным ключом, штампом времени и версией кэша, на котором они рассчитаны.  
При восстановлении канала Gateway отправляет события в Sync/Ingest API облака в исходном порядке, по принципу 
*at-least-once* с экспоненциальным backoff. Облако дедуплицирует их по идемпотентному ключу, поэтому повторная доставка 
не создаёт дублей.  
Порядок приоритетов при разгрузке очереди: сначала фискальные и платёжные документы (учёт и налоговая отчётность), 
затем лояльность, затем движение товаров и аналитика. Обратный поток — актуальные цены, промо и справочники — 
накатывается на кэш только после того, как очередь выгружена, чтобы не потерять привязку офлайн-чеков к ценам, 
действовавшим на момент продажи.
